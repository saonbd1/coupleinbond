# Bengali launch roadmap

## Goal

Launch a Bengali version of the site using translated core pages first, then move to original Bengali content per language after launch.

## Working principle

- Phase 1: bridge mode
  - translate only the most important pages
  - publish a usable Bengali experience
  - keep English as the source-of-truth for product structure
- Phase 2: independent content mode
  - English publishes original English content
  - Bengali publishes original Bengali content
  - stop relying on translation for new content

## Launch sequence

### Milestone 1 — bilingual foundation
- build / and /bn/ structure
- add language switcher
- localize homepage, about, calculator, polls, blog landing
- fix titles, meta descriptions, canonical URLs, and hreflang structure

### Milestone 2 — translated content launch
- translate the top 10 articles and key pages
- ensure Bengali UX feels natural and readable
- verify links, navigation, and shared assets

### Milestone 3 — original Bengali content starts
- publish Bengali-led content calendar
- create original Bengali article topics and poll ideas
- keep translated pages only where helpful as a bridge
- prioritize a few locally written pieces before expanding the full Bengali content library

### Milestone 4 — split editorial ownership
- English and Bengali each have their own production rhythm
- no new page is auto-translated unless explicitly marked as temporary bridge content
- keep the site SEO-safe by preserving canonical and hreflang metadata on every language version

1. confirm the current milestone
2. review the latest checkpoint
3. choose one next task only
4. verify links and page metadata before finishing
5. write the checkpoint note before stopping

This is intentionally lightweight so work can pause and resume without confusion.
## Content ownership model

- English: core brand, general relationship advice, broader SEO content
- Bengali: local cultural examples, Bengali tone, native workflows, original Bengali editorial identity

## Checkpoint workflow

Use the following for each work session:

1. review the current milestone
2. pick one active task only
3. complete that task and verify output
4. mark progress in this doc or the project todo tracker
5. write a brief checkpoint note before stopping

Example checkpoint note:

- Status: Bengali homepage structure done
- Last verified: navigation and language switcher tested
- Next action: translate calculator page
- Blocker: none
